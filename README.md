# 도의회 교육위원회 브리핑

전북특별자치도의회 **교육위원회** 회의록을 전북교육청 직원이 읽을 수 있게 정리한다.

> 도의회가 만든 자료가 아니다. 도의회가 공개한 회의록을 정리한 **비공식** 자료다.

- 공개 웹: `https://kain9012-bit.github.io/jbe-edu-committee/`
- 회의록 출처: [전북특별자치도의회 전자회의록](https://r.jbstatecouncil.jeonbuk.kr/main.do)
- 영상 출처: [인터넷 의사중계](https://live.jbstatecouncil.jeonbuk.kr/vod/list_standing_commitee.ifn?sch_scate_no=24)

---

## 이 서비스가 푸는 문제

교육위원회 회의는 한 번에 3~5시간이고, 본청 각 국·과와 직속기관·교육지원청이
차례로 답변한다. 그런데 **담당자가 자기 과에 무슨 질의가 나왔는지 알려면 회의록
전체를 읽어야 한다.** 회의록은 발간이 늦고, 발간돼도 한 덩어리 문서다.

그래서 회의록을 **부서별·의원별·안건별로 갈라 놓는다.**

## 왜 받아쓰기를 하지 않아도 되나

주간정책회의 프로젝트는 유튜브 영상을 받아써야 했다. 여기는 다르다.
전자회의록에 **공식 속기록 원문 XML** 이 그대로 공개돼 있다.

```
https://r.jbstatecouncil.jeonbuk.kr/data/6450000{cdFpath}{cdCode}.xml
```

발언자 이름·의원ID·안건 구분이 전부 태그로 붙어 있다. 오인식이 없으므로
**원문 인용이 100% 정확하다.** 부서별·의원별 집계도 규칙만으로 정확히 나온다.

### 다만 발간이 늦다

| 회의일 | 회기·차 | 발간일 | 지연 |
|---|---|---|---|
| 2026-07-30 | 430회 5차 | 08-14 | 15일 |
| 2026-07-20 | 430회 1차 | 08-14 | 25일 |
| 2026-06-11 | 428회 2차 | 08-04 | 54일 |
| 2025-11-17 | 423회 1차(행감) | 01-21 | 65일 |

최근 24건 지연 **중앙값 27.5일**. 정례회·행정사무감사철은 두 달을 넘는다.
영상은 다음 날 올라오므로, 그 공백은 **영상 음성을 받아쓴 임시본**으로 메운다.
속기록이 나오면 전문은 자동으로 교체되고, 화면 배지가 바뀐다.

**요약은 다시 쓰지 않는다.** 교체 때문에 사람이 두 번 일하지 않는다.

### 2단계 발간에 주의

`cdImsi` 가 `Y` 면 **임시회의록**(속기 미확정), `N` 이면 확정본이다.
임시본이 나온 뒤 수 주~두 달 뒤에 확정본으로 **본문이 교체된다.**
`collect.py` 는 이 전환을 감지해 다시 받는다.

```

  fetch_audio.py     영상 오디오 받기 (사용자 PC에서)
  transcribe.py      받아쓰기 + 화자 군집 (임시본)
data/

  records/<회의>.json      회의록 전문 (발언 단위)
  records/<회의>.asr.json  받아쓴 임시본
  meetings/<회의>.json     요약 — 사람이 쓴다
  derived.json       부서·의원·안건 집계 (35KB — 홈·안건 탭은 이것만 받는다)
  dialogs.json       주고받은 덩어리 (694KB — 부서별·의원별에서만 받는다)
  asks.json          지적·요구 + 집행부 답변 (61KB — 요약의 asks 에 답변을 붙여 만든다)
  human/<회의>.json   군집 → 화자 이름 (사람이 적는다)
```

## 회의 ID

`회기-차수`. 상임위는 `430-1`, 행정사무감사는 `2025K-1`.
행정사무감사는 전자회의록에서 `ctGroup=K, ctUid=33` 으로 따로 관리된다.
**이걸 빼먹으면 11월 행정사무감사 회의록이 통째로 누락된다.**

## 절차

### 1. 수집 (어디서나)

```bash
python collector/collect.py              # 새 회의만
python collector/collect.py --all        # 전부 다시
python collector/collect.py --with-stream  # 영상 스트림 주소까지
python collector/derive.py               # 부서·의원·안건 집계
```

### 2. 속기록이 아직 없을 때만 — 받아쓰기 (사용자 PC에서)

```bat
오디오받기.bat
```

스트림이 **7443 포트**로 나가서 클라우드에서는 못 받는다. ffmpeg 가 필요하다.

```bash
python collector/transcribe.py --id 430-6
```

3~5시간짜리 회의면 **2~4시간** 걸린다. 백그라운드로 돌린다.
화자 군집에 이름은 `data/human/<회의>.json` 에 사람이 적는다.
**추측해서 채우지 않는다.** 틀린 이름이 붙은 부서별 집계는 비어 있는 집계보다 나쁘다.

### 3. 요약 쓰기 — 여기가 사람이 하는 일

`data/meetings/<회의>.json` 을 직접 쓴다. LLM API 를 쓰지 않는다.

```json
{
  "id": "430-5",
  "summary": "이 회의가 무엇이었는지 3~5문장",
  "agenda": [{"title": "회의록 matters 그대로", "result": "원안가결|보류|보고 청취", "note": "한 문장"}],
  "highlights": [{"title": "…", "body": "…", "dept": "…", "member": "…",
                  "quote": "원문 그대로", "speaker": "…", "turn": 3}],
  "asks": [{"type": "자료요구|지적사항|요청", "dept": "…", "member": "…",
            "title": "미디어 리터러시 위탁교육 집행 내역 자료 제출 요구",
            "body": ["전북대 산학협력단 위탁, 예산 2억 원 규모",
                     "업무보고에 집행 내역·핵심 교육내용 미기재",
                     "세부 내역 제출 필요"],
            "quote": "원문 그대로", "speaker": "…", "turn": 4}]
}
```

`asks` 는 **개조식**으로 쓴다. `~지적이 있었다` 같은 서술형 종결을 쓰지 않는다.
제목은 명사형으로 끝내고(`~제출 요구`, `~확인·설명 필요`, `~재발방지 대책 마련 필요`),
본문은 2~4줄로 ①무엇이 문제인지 ②근거·수치 ③무엇을 해야 하는지 순으로 적는다.
한 줄짜리 서술문 하나만 두면 목록을 훑어도 무슨 내용인지 알 수 없어 결국 회의록을 다시 열게 된다.
`verify.py` 가 서술형 종결과 빈 본문을 잡는다.

### 4. 검증 — 반드시 통과시킨다

```bash
python scripts/verify.py
```

```bash
npm run build      # 화면 빌드 확인
```

## 절대 규칙

1. **인용문을 지어내지 않는다.** `quote` 는 회의록에 **글자 그대로** 있어야 한다.
   `verify.py` 가 검사한다. 지어낸 인용 하나가 이 서비스의 신뢰를 통째로 무너뜨린다.
2. **추측을 확정처럼 보이게 하지 않는다.** 근거가 없으면 비워 둔다.
   부서 이름이 비슷하다는 이유로 발언을 그 부서에 붙이지 않는다.
3. **자료가 오기 전에는 빈 껍데기를 쓴다.** 그럴듯한 표본을 채워두면
   못 받았을 때 가짜가 진짜처럼 보인다.
4. **없으면 없다고 말한다.** 속기록이 안 나온 회의를 목록에서 빼지 않는다.
   빼면 "그 날 회의가 없었나 보다" 로 읽힌다.
5. **오디오는 저장소에 넣지 않는다.** 의사중계에서 언제든 다시 받을 수 있다.

## 화면에서 지키는 것

첫 판을 만들어 놓고 사용자 입장에서 눌러 보니 여섯 가지가 걸렸다. 그때 정한 규칙이다.

1. **간판과 결과가 어긋나면 안 된다.** "우리 과에 무엇을 물었나" 라고 해 놓고 과를 누르면
   1건뿐이면, 없는 것보다 나쁘다. 답변한 사람의 소속만 보지 말고 **언급된 부서**까지 센다.
2. **확실한 것과 불확실한 것을 섞지 않는다.** 질의–답변 짝이 확실한 것(69%)만 나란히 두고,
   나머지는 답변만 싣고 "앞뒤는 회의록에서 보라"고 말한다.
3. **화면 상태는 주소에 담는다.** 링크를 못 주면 조직 안에서 퍼지지 않는다.
   해시(`#/dept/교원인사과`)를 쓴다 — Pages 는 정적 호스팅이라 실제 경로는 404 가 난다.
4. **추천 검색어는 데이터에서 뽑는다.** 그럴듯해 보인다고 손으로 적으면 결과 0건인 칩이
   첫 화면에 뜬다. 실제로 `#급식` 이 그랬다.
5. **기본 회차는 가장 알찬 것으로.** 가장 최근 회차를 기본으로 뒀더니 발언 6건짜리가 걸려서
   첫인상이 "내용이 이것뿐인가" 였다.
6. **자주 볼 것을 안쪽에 숨기지 않는다.**
   위원 지적·자료요구를 안건 탭의 두 번째 칩에 넣어 뒀더니 아무도 못 찾았다.
   집행부가 실제로 받아 가야 할 숙제인데 안건 이력보다 안쪽에 있었다. 독립 탭으로 올렸다.
7. **회차로 좁힐 수 있어야 한다.** 부서별·의원별이 전 회차 합계만 보여줬다.
   "이번 회기에 우리 과에 뭐가 나왔나" 가 안 됐고, 회의가 쌓일수록 나빠질 문제였다.
   좁히면 목록·숫자·펼친 내용이 **한꺼번에** 그 회차 것만 남는다.
8. **쓰지 않는 자료를 받지 않는다.** 어느 탭에 있든 기본 회차 전문(555KB)을 받고,
   안건 탭은 쓰지도 않는 질의응답 897KB를 받고 있었다. 파일을 쪼개고 탭별로 갈랐다.

   | 탭 | 전 | 후 |
   |---|---|---|
   | 홈 | 1,475KB | **42KB** |
   | 안건 | 1,577KB | **145KB** |
   | 지적·요구 | — | **110KB** |
   | 통합검색 | 2,200KB | 1,631KB |

9. **사람이 읽는 단위로 묶는다.** 집행부 답변 하나마다 카드를 만들었더니, 같은 주제로
   열 번 주고받은 대목이 열 개 카드로 쪼개졌다. 그러면 회의록 전문에 필터만 씌운 것과
   다를 게 없다. 위원회는 위원장이 "○○ 위원님 질의해 주시기 바랍니다" 하고 넘기면
   그 위원이 한 부서를 끝까지 파고드는 구조다. **그 단위가 카드 하나다.**
   덩어리는 다른 위원이 나설 때, 안건이 바뀔 때, 그리고 **위원이 다른 부서를 부를 때** 끊는다.
   1,005개 카드가 133개 덩어리(평균 15발언)가 됐다.
10. **요구만 싣고 답을 빼지 않는다.** 지적·요구 카드에 위원 발언만 한 줄 인용해 뒀더니,
    받아 갈 사람이 "그래서 뭐라고 했는데?" 를 알 수 없었다. 회의록에서 그 발언 **바로 뒤에
    이어지는 집행부 발언**을 찾아 함께 싣는다(63건 중 58건에 답변이 붙었다).
    답변이 없는 자리(마무리 당부·처리의견)는 없다고 밝힌다. 지어내지 않는다.
11. **읽는 사람이 할 수 있는 일이 없으면 화면에 두지 않는다.**
   임시회의록인지 확정본인지를 목록마다 노란 배지로 달았더니, 둘 다 도의회 공식 회의록이고
   확정본이 나오면 알아서 갈리는데 경고색만 남아 불신을 샀다. 배지를 뺐다.
   딱 한 사람 — **그 문장을 보고서에 옮겨 적는 사람** — 에게만 필요하므로,
   회의록 전문 화면에만 회색 한 줄로 남겼다.

## 수집기가 조용히 틀리는 자리

- **VOD 목록의 `sch_daesu_no` 와 `sch_period_no` 가 안 맞으면 에러 없이 0건이 온다.**
  대수 ID 는 대수 숫자와 다르다 (13대 = 12).
- **회의록 API 의 `cvUid` 는 교육위 전건 `null`** 이다. 회의록↔영상 공식 연결이 없어서
  `(회기, 차수, 날짜)` 로 직접 조인한다.
- **VOD 챕터(발언자 인덱스)는 2026-04-15 이후 교육위 영상에 없다.** 있으면 쓰고
  없으면 그만이지, 여기에 기대는 기능을 만들면 안 된다.
- **오전·오후로 나뉜 영상은 회의록 1건에 영상 2건**이 대응한다 (목록 제목의 `#2`).
- **같은 조례안인데 회차마다 제목 표기가 다르다.** 2차는 `(전북특별자치도교육감)`,
  4·5차는 `(전북특별자치도교육감 제출)(계속)`. 제안자 표기를 떼지 않으면 이력이 끊긴다.
- **회의록 XML 의 `<name>` 에 발언자가 아닌 지문이 들어오는 자리가 있다.**
  `(집행부석에서 "생존수영…")` 같은 것. 새 발언으로 세면 있지도 않은 발언자가 목록에 생긴다.
  앞 발언에 이어 붙인다 — 버리면 말이 사라진다.
- **소속은 떼어낸 직함에서 먼저 찾고, 실패할 때만 발언자 문자열 전체를 본다.**
  `교육연수원장` 처럼 **끝나는 말**로 기관을 알아내는 규칙이 있어서 이름이 붙어 있으면 깨진다.
  반대로 `교원인사과유·초등인사담당` 은 직함을 못 떼어내므로 전체를 봐야 잡힌다.
- **회의록을 다시 받으면 발언 번호가 밀릴 수 있다.** 요약의 `turn` 은 인용문으로 다시 찾아
  맞춰야 한다(`verify.py` 가 어긋난 것을 잡는다).
- **`.gitignore` 에 `*.ts` 를 넣지 마라.** HLS 조각 파일 확장자가 `.ts` 라서 거르려다가
  타입스크립트 소스가 통째로 빠졌고 첫 배포가 죽었다. 조각은 `data/audio/` 안에만 생긴다.
